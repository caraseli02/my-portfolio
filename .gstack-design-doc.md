## Problem Statement

Transform a static Vue 3 portfolio into an interactive, chat-enabled portfolio. Visitors (recruiters, developers, clients) can ask questions about the developer's work and get informed answers via a website chat widget. Later, add an MCP server for Claude Desktop power users.

## What Makes This Cool

The portfolio doesn't just sit there. It talks back. A recruiter visits the site, clicks the chat bubble, asks "what's this developer's strongest project?" and gets a detailed answer with links to the actual case study. Every visitor gets this, not just Claude Desktop users. Later, the same portfolio data powers an MCP server for Claude users who want deeper interaction.

## Constraints

- Ship Phase 1 (chat widget) this week
- Use Vercel for hosting (promo credits available)
- Start with Claude API for chat; add provider abstraction later if needed
- Portfolio data in `src/data/projects.ts` (3 projects, rich narratives, timelines, outcomes, tech stacks)
- Vue 3.5 + Vite + Tailwind 4 + TypeScript 5.8 stack
- No external DB needed (data fits in context window)

## Premises

1. MCP is the right protocol — portfolio data becomes tools, interactive views become UI resources
2. Vercel serverless hosts the MCP server — Express → Vercel Function mapping, `/mcp` endpoint
3. Model-agnostic via abstraction — test cheap, ship Claude
4. Chat widget is the right website UX — floating bubble, familiar pattern
5. Portfolio data (3 projects) is sufficient — no RAG, no vector DB
6. Phased delivery de-risks MCP Apps learning curve

## Architecture

### Phase 1: Website Chat Widget (Week 1, 2 days)

**Chat Component** (Vue 3):

- `ChatWidget.vue` — floating bubble bottom-right, opens slide-in drawer (desktop: 400px wide, max 70vh; mobile: full-screen overlay)
- `ChatMessage.vue` — message bubble with markdown rendering, user right-aligned (primary color), bot left-aligned (surface color + glass)
- `ChatInput.vue` — input field with send button, uses existing form styling

**Chat states:**

1. Welcome/empty — system greeting ("Hi, I'm Vlad's portfolio assistant.") + suggested prompts
2. Streaming — typing indicator transitioning into progressive text rendering
3. Error — inline error with retry button
4. Post-answer CTA — after 3rd exchange, surface "Schedule a call" or "View case study" link

**Design system bindings:**

- Chat panel: `.glass` + `backdrop-blur-lg`
- Bot messages: `--color-surface` background
- User messages: `--color-primary` background, white text
- Panel open animation: `--animate-slide-up`
- Message appear: `--animate-fade-in`
- Dark mode: respects existing dark mode toggle

**Backend:**

- Vercel Edge Function at `api/chat.ts`
- Uses Vercel AI SDK (`ai` package) with `streamText()`
- System prompt includes full portfolio context (projects data, bio, skills)
- Model: Claude API (Anthropic) — single provider, no abstraction
- Rate limiting via Vercel Edge Middleware (non-negotiable)

**Data layer:**

- Portfolio data via `tsconfig.paths` + Vercel `includeFiles` (single source of truth)
- No data copying — import directly from `src/data/projects.ts`

**Security:**

- Rate limiting via Vercel Edge Middleware
- No API keys exposed to client
- Sanitize user input before sending to model

**Deployment:**

- Vercel project (new or linked to existing repo)
- Edge function at `api/chat.ts`
- Chat widget bundled with main Vite build

**Testing:**

- Manual: open portfolio, click chat bubble, ask questions
- Verify streaming, error states, mobile responsive, rate limiting

### Phase 2: MCP Server (Week 2, 2 days)

**MCP Server** deployed as Vercel Serverless Function:

- Endpoint: `POST /api/mcp`
- Transport: SSEServerTransport (stateless, serverless-safe). Validate StreamableHTTP first, fallback to SSE.
- Tools:
  - `get_projects` — returns list of all projects with summaries
  - `get_case_study` — returns full case study by slug. Error response for invalid slug: `{ isError: true }`
  - `get_tech_stack` — returns tech stack for a project
  - `search_projects` — case-insensitive partial match on title/description/tech/category. Empty string returns error. Max 10 results.
- UI Resources (MCP Apps extension) — **validate Claude Desktop renders `ui://` before building**:
  - `ui://project-card` — interactive project card HTML
  - `ui://case-study-timeline` — interactive timeline HTML
  - `ui://tech-radar` — tech stack visualization HTML

**Compute model:**

- Serverless (not Edge) for MCP — MCP Node SDK requires Node.js runtime

**Data layer:**

- Same as Phase 1: `tsconfig.paths` + `includeFiles`
- Pre-compute all tool responses at module load time
- Pin exact versions for all MCP deps

**Testing:**

- Unit tests for each tool (input/output contracts)
- Integration test: `initialize` + `tools/list` + `tools/call` sequence
- Claude Desktop connector test
- Build-time check that UI resource bundles exist
