# Impeccable Design Context

## Users

Recruiters and hiring managers evaluating a Vue.js / frontend specialist. They scan fast, often on laptops, comparing dozens of portfolios. Their context: mid-task, time-constrained, looking for signals of craft and competence. The portfolio must hook them in under 10 seconds — then reward deeper inspection from technical recruiters and staff-level engineers who read source and test keyboard shortcuts.

## Brand Personality

Technical, dense, impressive — delivered through editorial composure. The interface should feel like a well-set magazine page that a senior engineer would build for themselves: intentional typography, confident whitespace, and hidden technical affordances (shortcuts, real monospace, live stats) that reward the curious. Not flashy for its own sake, but the kind of dense that signals deep expertise. Think: the person who reads source code for fun.

## Aesthetic Direction: Hybrid — Editorial Skeleton + Terminal Organs

**Editorial skeleton** (what the interface looks like at a glance):

- Serif display face for h1/h2 (keep Young Serif or a deliberate alternative — serif chosen on purpose, not by default)
- Cream `#f5f0e6` / charcoal dual-theme, raw cobalt `#1f32ff` accent
- Magazine-style asymmetric grids, generous vertical rhythm, editorial kickers as section labels
- `CaseStudyListItem`-style alternating-reverse compositions as the base pattern for lists
- Solid surfaces over cream (no ambient glass); card chrome used sparingly, not as the default wrapper

**Terminal organs** (what the curious visitor discovers):

- **Real monospace face** for code, stats, metadata (JetBrains Mono / Geist Mono / IBM Plex Mono — NOT Figtree aliased as `--font-mono`)
- Dense **stats strip** under the hero name: years, stack, project count, location — scannable in 2 seconds
- **⌘K command palette** with nav + case-study jump + theme toggle
- `j`/`k` between case studies, `?` for shortcut legend
- Live code snippets and mono code-blocks inside case studies as embedded evidence, not decoration
- Custom cursor and other pointer affordances are **opt-in**, not forced

## Design Principles

1. **Editorial calm carries terminal density.** The base layer reads like a magazine. The content layer (stats, code, shortcuts, live demos) supplies the technical punch. Neither fights the other.

2. **Every mono surface must be mono.** If it's labeled `font-mono` or styled as code/metadata, it must render in a real monospace. No sans aliased as mono.

3. **Interactive proof over claims.** Live code snippets, working demos, keyboard shortcuts, and real metrics replace bullet-point skill lists. Show, don't tell.

4. **Recruiters scan in 10 seconds, devs inspect in 10 minutes.** Surface `name → stack → years → case-study count → availability` above the fold. Reward deeper inspection with density: shortcuts, mono code, source links, ship cadence.

5. **Dual-theme as craft signal.** Light and dark modes both fully realized, with a transitioned toggle (not an instant flip). The mode switch is itself a small showcase of frontend polish.

6. **Opt-in, not forced.** Custom cursor, motion, and any expressive affordance must respect `prefers-reduced-motion` and offer an explicit user toggle. Default OFF for first-time visitors.

7. **One design system across every route.** Home, Projects, and Case Studies must feel like the same site. If a page still uses an older system, it is a trust-break — rewrite or delete.
